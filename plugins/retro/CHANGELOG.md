# Retro changelog

## 0.2.0 (2026-11-19)

- Added: `/retro:board`, a shared board of facts for a main agent and its sub-agents. `scripts/board.py` is one append-only JSONL file in the run folder: `add` (a key, a one-line value, who, the evidence, a level: reproduced, read or claimed), `get` (a key or a prefix, each read logged with who asked), `seed --from context.json` (the facts of `/inspector:audit`'s context), `show`. A new value supersedes the old one and both are kept (`get --history`); the same value again writes nothing; a value or evidence that looks like a token, a bearer value, a private key or an Azure DevOps PAT is refused. Each record is one locked append (`fcntl` on POSIX, `msvcrt` on Windows): 60 writes from 6 processes at once all land with unique ids (`tests/test_board.py`). The locking on Windows was not run here.
- Added: `agents.py --board FILE`. Per agent: board reads and writes; a command it ran for a fact already on the board when it started (owned by **execution** if its brief named the board, by **brief** if not); "brief has no Board line" when the run used a board; a verifier (by type or description) that read the board before its own first check, under **execution**.
- Changed: the brief contract has an optional `Board:` line, and says a verifier reads the board only after it has its own answer.
- Added: `add` refuses (exit 2) a new key for an attribute the board already holds under another namespace (`repo.default_branch` while `git.default_branch` exists), naming that key and its value; `--new-key` writes it anyway for a different fact. Keys that differ in a name in the middle (`git.branch.a.on_remote`, `git.branch.b.on_remote`) are different facts. `show` lists pairs written with `--new-key` as "same fact, two keys" or "conflict". `keys` prints the current keys for a brief, and the board skill, the brief contract and `/inspector:audit`'s brief template put them in the brief.
- Fixed (the factory's review of #149, code and security):
  - `agents.py` matched a board fact's command to a call by substring in both directions, so `ls` matched `git ls-remote --heads`, and Grep or Glob searches matched evidence too. It now matches only when the evidence's words open one of the call's shell commands (`same_command`).
  - Re-deriving a fact already on the board is counted (`board.reran_known`), not blamed. The briefs ask an auditor to cite a record it read itself and a verifier to re-derive, so this was blaming the agents for what they were told to do. What is blamed under execution is a brief that named the board and an agent that never read it; verifiers are exempt.
  - A fact written in the same second an agent started counted as unknown (`0 or -1`).
  - With `--all`, one board was applied to every session; it now applies only to the session whose time span holds its facts.
  - The board refused `az.version` after `gh.version` and told the agent to use the other key, which would overwrite one tool's fact with another's. It now refuses only when the value is the same, and lists a pair with different values for checking.
  - `seed` turned `feat/x` and `feat-x` into one key, and two worktrees with the same folder name into one key. It also dropped a remote with capital letters in its name. Slugs now keep `/` and `.` and are lowercased, a name with capitals gets a short hash (`Feat` and `feat` stay two keys), and a worktree is named by its path inside the repository.
  - `get --history` re-read the board for every row it printed.
  - The audit skill's brief named `ado.org.<org>.project`, while `seed` writes `ado.org.<org>`.
  - `get <prefix>*` in the docs is now quoted, since an unquoted glob fails in zsh or expands to a file name.
  - A secret in a key or in `--by` was not checked (security, minor).
  - On Windows the lock gave up after 10 s and wrote without it; it now raises after 60 s and writes nothing (security, minor; tested with a stand-in `msvcrt`, not on Windows).
- Fixed (agent-audit on a real factory review, 2026-11-19): `agents.py` saw 5 of the session's 8 sub-agents. The three the factory started (code, security, skeptic) have transcripts in `subagents/` but no Agent call in the main transcript. They are now read from the folder too, with the brief from the first message and the type, model and `pluginSteered` from the meta, and attributed to their plugin (`factory (plugin)` in the By skill table). On that run, six of the audit's flags were its own false positives, each fixed with a test built from the run's shape:
  - "the brief named the board": the reviewers' brief described `board.py`, because it was the feature under review. Only a `Board:` line counts now.
  - "no Board line" for agents started before any board existed: now only with `--board`, and only for agents started after its first fact.
  - "the same call 3x": one patch read in three ranges. Calls are compared with their whole input now.
  - "also run by siblings": the reviewers read the same diff. Only shell commands count; both reviewers running the same test suite still counts, as duplicated work.
  - "deliverable": a path that appeared near "write" in the description of the change. Deliverables come from a `Deliverables:` line or a path right after write, save or create.
  - "unrecovered failure": a last command that failed and was explained in the report. A last failure counts only when the report does not mention it.
  - A brief without the contract's labels (Context, Rules, numbered asks, deliverable paths) is shape, not a problem: those are shown under `brief_checks`, and only a missing budget is a brief problem.
  What stood on the factory: none of its three agents' briefs sets a tool-call budget; measured, code 11 calls, security 7, skeptic 31.
- Measured in one live trial (2026-11-19, two haiku sub-agents, a board seeded with the default branch): the checker read the board first and did not look the branch up again, and added its count with the command behind it; the verifier made its own two counts before reading the board, and confirmed. `agents.py --board` flagged neither. The checker also wrote the branch a second time as `repo.default_branch`, because the brief named no keys: the refusal above and the Keys line came from that. A second trial with the same brief (naming no keys) and the refusal in place: the checker tried `repo.default_branch`, was refused with `git.default_branch = main` named, read the board and wrote only its count; the board ended with two facts and no duplicate. Two trials on a trivial task, not a measurement of what the board saves.

## 0.1.0 (2026-11-19)

- Added: `/retro:distill`. `scripts/trace.py` digests a finished run's transcript: the task, the steps (repeats collapsed), each failure and the call after it, calls tried 3+ times, blocked calls, skills and sub-agents, the final answer. It reads Claude Code sessions (sub-agents from `<session>/subagents/`), role/content JSONL, and plain-text or markdown exports such as a Cursor chat, where each command's following prose is kept as what it observed. Emails, GUIDs, tokens, session links and user names in paths are masked. The skill drafts a SKILL.md (facts to resolve first, procedure, rules, gotchas, output, budget) under the scratchpad, lints it and installs it only on yes, for Claude Code or Cursor; `--update` turns a run into a diff to the skill it used and a row in that skill's run log.
- Added: `scripts/lint_skill.py`: frontmatter, a name that matches the folder, every `scripts/` or `references/` path the text names exists, and no private data (emails, GUIDs, tokens, session links, home paths) anywhere in the folder; warnings for no procedure, gotchas, output or budget.
- Added: `/retro:agent-audit`. `scripts/agents.py` measures each sub-agent from its own transcript: calls without its hand-back call, failures, the same call 3+ times, minutes, the budget its brief declared, the files it was asked for, writes and mutating commands under a read-only brief, its own count against the transcript's and the host's. Each problem gets an owner: brief (no budget, asks or deliverable paths, no context or rules, commands the main agent had already run, or that sibling agents each ran), execution, host (blocked, 401/403, a CLI missing) or model (a small model struggling on a clear brief; a large one finishing a trivial one). It records which skill was loaded when each brief was written, and rolls agents up by skill and by model: with `--all --skill NAME`, an eval of that skill's briefs across sessions. `--reports DIR` reads end-of-run report files for hosts whose sub-agent transcripts can't be read.
- Added: `references/brief-contract.md`, the brief shape (goal, context, numbered asks, rules, budget, deliverables, report file) and the report file's schema, used by `/inspector:audit`.
- Measured on one session (2026-11-19): a probe sub-agent's report said 4 tool calls, its transcript 3 and the host 3; the difference was its hand-back call, which the audit now names.

# Retro changelog

## Unreleased

- Fixed (security): `mask()` let through a lower-case `bearer` value, `X-Api-Key` headers, and `npm_`, `sk_`/`rk_` live or test, `AIza` and `ASIA` keys. Inspector's copy of this masker (`decide.py`) gained them in #199; retro hadn't. `TOKEN_RE` and `BEARER_RE` are now the same patterns as inspector's, and `X_API_KEY_RE` is added. Found by an `/inspector:inspect` run on 2026-11-25 (verified REAL-LOW). Ten rows in `tests/test_mask_secrets.py` fail on the code before this change, in all three paths (mask, both digest formats, the CLI). Four more rows check that prose (`the bearer of bad news`, `npm_install`) stays readable. Inspector's heuristic rules (password flags, JSON keys, env assignments, URL userinfo, query strings, AWS, Azure) are not ported here. The factory review of #207 found that inspector's `\b` before `Bearer`, once copied, stopped masking a token in the text json.dumps gives (`\nBearer <token>`, which `Call.brief()` falls back to). The old retro rule had no `\b` and masked it. The `\b` is gone from both copies, and from `X_API_KEY_RE`; `lint_skill.py` also refuses an `X-Api-Key` header, and the new patterns have hostile-input rows in `test_mask_redos.py`.
- Fixed (security, #198): `mask()` left a `curl -u` credential in an argument list visible when the list was cut off inside the value (a digest caps long lines): `ARGV_USER_RE` needed a closing quote after it. The value now also ends at a line end or the end of the text, after an optional backslash. Seven rows in `tests/test_mask_redos.py` (`cut-*`: after a backslash, no closing quote, after an escaped backslash, at a newline, the `json.dumps` and single-quoted forms) fail on the code before the fix. A value cut right after a backslash is masked with that backslash.
- Fixed: the digest's "Blocked or denied" listed calls whose output only mentioned a word like `blocked` or `permission` (a real digest listed GitHub's `mergeable_state: blocked` twice, and a grep that quoted refusal phrases from source code), while they had succeeded. A failed call is still listed on those words. A call that succeeded is listed only when its first line says it was refused where a refusal is written: at the end (`cat: /x: Permission denied`, `Operation not permitted`, git's `returned error: 403`) or at the start after an optional `program: ` prefix (`request blocked`, `HTTP 403:`, `403 Forbidden`, `Permission to o/r.git denied`, Claude Code's "Permission for this action was denied"). The factory review of #205 found the first version missed the two-prefix shell form, and listed `forbidden_words.py` and `403 lines`. A text transcript, which has no exit status, keeps the word rule. `tests/test_trace_blocked.py` holds the rows, four of them real results from that session; on the code before this fix 7 of its 11 tests fail.

## 0.3.0 (2026-11-20)

`/retro:distill` routes each lesson to where it holds (a check, a test, access, guidance, a skill, a model choice or no change) before drafting a skill; masking covers private keys and Azure DevOps PATs and keeps JSON valid; agent-audit splits resumed agents, judges scratch by location and reports what it could only take on the agent's word; the board shows disagreements between writers.

- Fixed: `/retro:agent-audit` treated any path containing `scratchpad`, `/tmp/` or `/temp/` as scratch, so a read-only agent's write to `src/scratchpad.py` or `src/temp/app.py` raised no violation. A write is now resolved against the agent's folder. Inside that folder only `.inspector-run/` is scratch, even when the repository itself is under a temp folder. Outside it, a system temp root (`/tmp`, `/var/folders`, Windows `AppData\Local\Temp`, an unexpanded `$env:TEMP`) or a `scratchpad` folder counts. Path components are compared, not substrings.
- Fixed: `--json` output of `trace.py` and `agents.py` was masked as text after it was serialized. A string ending in a backslash, next to a cut-off private key, then produced invalid JSON (exit 0). JSON is now masked value by value before it is serialized. Text output is masked as before.
- Fixed: masking a private key cut off before its END line took the rest of the line with it, which broke a JSON transcript line. It now stops at the end of the string the key is in.
- Fixed: `/retro:agent-audit` counted a write to `/tmp/../<repo>/file` as a scratch write, because it matched `/tmp/` in the text. The path is normalized first.
- Fixed: `lint_skill.py --recommendations` passed an empty `evidence:` or a `->` with no target. And distill no longer asks to lint a skill folder when no lesson went to *skill*.
- Changed: `/retro:distill` routes each lesson before it drafts anything. After reading the project's checks, CI and docs, it gives each lesson one destination: an existing check to fix or wire in, a new test or lint rule, missing access or navigation docs, guidance in a brief, a skill, a model choice, or no change yet. Only *skill* lessons go into a SKILL.md draft. Each recommendation names its evidence, what was measured (kept apart from the hypothesis), what was already there, the change and its target, why, and how to verify it (`references/recommendations.md`), and `lint_skill.py --recommendations` checks it. `/retro:agent-audit` maps its owners onto the same destinations. Idea from comparing with mattpocock/skills' retro, which routes lessons into checks first.
- Fixed: `lint_skill.py .` read the folder's name as empty.
- Fixed: a resumed agent's calls were split between its dispatches by comparing timestamps as text, so `…:01.5Z` sorted before `…:01Z` and `+00:00` against `Z` went by the wrong order. They are compared as instants now.
- Fixed: a writer replacing its own value on the board erased its disagreement with another writer (A writes X, B writes Y, B writes Y2). The disagreement now follows the writer's own refreshes back to the value they replaced, until a resolution or the other writer's confirm settles it.
- Fixed (#163): transcript discovery fell back to every project when the requested one had none, and always added every Cursor project, so `--latest` could read another project's session. A project that is named stays inside it: no match is an empty list; a Cursor folder counts only when its name is the project's; `--everywhere` (trace.py, agents.py) lists all on purpose.
- Fixed (#164): a resumed sub-agent was counted once per dispatch with its whole transcript each time. Dispatches of one agent id now split its calls by launch time, so each call is counted once, against the brief and budget it was made under; rows read `<id>#1`, `<id>#2`.
- Fixed (#165): the digest mask and the skill lint missed private-key blocks and the Azure DevOps PAT shape the board refuses. One rule set (`PRIVATE_KEY_RE`, `ADO_PAT_RE` in transcript.py) masks the whole key block and the PAT in both digest formats, and the lint refuses either in any file of the skill without printing it.
- Fixed (#166): the rollups counted a report-only agent as clean with a 0% failure rate. They now carry `observed` and `reported_only`, the failure rate is unknown (`?`) with nothing observed, only observed agents can be clean, and a budget built on self-reported counts says how many.
- Fixed (#167): a budget in turns was compared with a count of tool calls. Only a budget in tool calls is checked now; a turn budget is flagged as not checkable from calls, and the model hint follows the same rule.
- Fixed (#168): the read-only check allowed any write whose file name matched a deliverable. Whole paths are compared now, resolved against the agent's folder, and a write the host refused is listed as `refused_writes`, an attempt, not a change.
- Fixed (#169): report files were matched to transcript rows only by the host's agent id, so a report named by its brief label became a second row. They now join by the brief's `Report file:` name, the agent id or the description, only when exactly one row matches; an ambiguous or unmatched report says so.

- Fixed (#162): two writers giving one key different values left only the last value in `show`, with no notice. A current fact that replaced another writer's different value is now a disagreement: `show` prints both values with their writers and evidence, and `get` carries it as `conflict`. It is settled by `add ... --resolve "<why>"` (on the new value or a confirm of it) or by the first writer confirming the new value; one writer replacing its own value is a refresh, and the same value is a confirm. History is kept.
- Fixed (#157): under `--min-level L`, `--max-age` counts only confirms at level L or above, so a claimed confirm no longer makes a reproduced fact look fresh. `seed` writes each fact and confirm at the context's `window.now` (with the time it ran as `recorded`), so re-seeding an old context never refreshes it. A `--max-age` too large for a date is refused (`refused:`, exit 2) instead of an `OverflowError` traceback.
- Fixed: a new record's id came from the count of parsed lines, so a line that won't parse could make two records share an id. Ids are now one more than the highest on the board.

- Added: confirms on the board. An `add` with the value a key already has appends a `confirm` record (key, value, the fact's id, who, evidence, level, time), through the same refusals and lock as any `add`. `get` (text and `--json`: `last_confirmed`, `confirms`) and `show` give each fact's last-confirmed time and confirm count, and `show`'s header counts confirms. `get --max-age MINUTES` returns only facts written or confirmed in the last MINUTES minutes, for volatile facts such as branch state; the read log records `max_age`. A confirm does not change the fact's level, and a superseding fact starts with no confirms. The inspector's copy of `board.py` is updated with it.
- Changed: a same-value `add` now returns `confirmed` (CLI: `confirmed: <key> = <value> (fact #<id>)`) and appends a record; it was `exists` and wrote nothing. `seed` counts `confirmed` instead of `exists`. `get` refusals (a secret in `--by` or the pattern, a bad `--max-age`) now print `refused: ...` and exit 2 instead of a traceback.

## 0.2.0 (2026-11-19)

- Added: `/retro:board`, a shared board of facts for a main agent and its sub-agents. `scripts/board.py` is one append-only JSONL file in the run folder: `add` (a key, a one-line value, who, the evidence, a level: reproduced, read or claimed), `get` (a key or a prefix, each read logged with who asked), `seed --from context.json` (the facts of `/inspector:audit`'s context), `show`. A new value supersedes the old one and both are kept (`get --history`); the same value again writes nothing; a value or evidence that looks like a token, a bearer value, a private key or an Azure DevOps PAT is refused. Each record is one locked append (`fcntl` on POSIX, `msvcrt` on Windows): 60 writes from 6 processes at once all land with unique ids (`tests/test_board.py`). The locking on Windows was not run here.
- Added: `agents.py --board FILE`. Per agent: board reads and writes; a command it ran for a fact already on the board when it started (owned by **execution** if its brief named the board, by **brief** if not); "brief has no Board line" when the run used a board; a verifier (by type or description) that read the board before its own first check, under **execution**.
- Changed: the brief contract has an optional `Board:` line, and says a verifier reads the board only after it has its own answer.
- Added: `add` refuses (exit 2) a new key for an attribute the board already holds under another namespace (`repo.default_branch` while `git.default_branch` exists), naming that key and its value; `--new-key` writes it anyway for a different fact. Keys that differ in a name in the middle (`git.branch.a.on_remote`, `git.branch.b.on_remote`) are different facts. `show` lists pairs written with `--new-key` as "same fact, two keys" or "conflict". `keys` prints the current keys for a brief, and the board skill, the brief contract and `/inspector:audit`'s brief template put them in the brief.
- Fixed (the factory's review of #149, code and security):
  - `agents.py` matched a board fact's command to a call by substring in both directions, so `ls` matched `git ls-remote --heads`, and Grep or Glob searches matched evidence too. It now matches only when the evidence's words open one of the call's shell commands (`same_command`).
  - Re-deriving a fact already on the board is counted (`board.reran_known`), not blamed. The briefs ask an auditor to cite a record it read itself and a verifier to re-derive, so this was blaming the agents for what they were told to do. What is blamed under execution is a brief that named the board and an agent that never read it; verifiers are exempt.
  - A fact written in the same second an agent started counted as unknown (`0 or -1`).
  - With `--all`, one board was applied to every session; it now applies only to the session whose time span holds its facts.
  - The board refused `az.version` after `gh.version` and told the agent to use the other key, which would overwrite one tool's fact with another's. It now refuses only when the value is the same, and lists a pair with different values for checking.
  - `seed` turned `feat/x` and `feat-x` into one key, and two worktrees with the same folder name into one key. It also dropped a remote with capital letters in its name. Slugs now keep `/` and `.` and are lowercased, a name with capitals gets a short hash (`Feat` and `feat` stay two keys), and a worktree is named by its path inside the repository.
  - `get --history` re-read the board for every row it printed.
  - The audit skill's brief named `ado.org.<org>.project`, while `seed` writes `ado.org.<org>`.
  - `get <prefix>*` in the docs is now quoted, since an unquoted glob fails in zsh or expands to a file name.
  - A secret in a key or in `--by` was not checked (security, minor).
  - On Windows the lock gave up after 10 s and wrote without it; it now raises after 60 s and writes nothing (security, minor; tested with a stand-in `msvcrt`, not on Windows).
- Fixed (agent-audit on a real factory review, 2026-11-19): `agents.py` saw 5 of the session's 8 sub-agents. The three the factory started (code, security, skeptic) have transcripts in `subagents/` but no Agent call in the main transcript. They are now read from the folder too, with the brief from the first message and the type, model and `pluginSteered` from the meta, and attributed to their plugin (`factory (plugin)` in the By skill table). On that run, six of the audit's flags were its own false positives, each fixed with a test built from the run's shape:
  - "the brief named the board": the reviewers' brief described `board.py`, because it was the feature under review. Only a `Board:` line counts now.
  - "no Board line" for agents started before any board existed: now only with `--board`, and only for agents started after its first fact.
  - "the same call 3x": one patch read in three ranges. Calls are compared with their whole input now.
  - "also run by siblings": the reviewers read the same diff. Only shell commands count; both reviewers running the same test suite still counts, as duplicated work.
  - "deliverable": a path that appeared near "write" in the description of the change. Deliverables come from a `Deliverables:` line or a path right after write, save or create.
  - "unrecovered failure": a last command that failed and was explained in the report. A last failure counts only when the report does not mention it.
  - A brief without the contract's labels (Context, Rules, numbered asks, deliverable paths) is shape, not a problem: those are shown under `brief_checks`, and only a missing budget is a brief problem.
  What stood on the factory: none of its three agents' briefs sets a tool-call budget; measured, code 11 calls, security 7, skeptic 31.
- Measured in one live trial (2026-11-19, two haiku sub-agents, a board seeded with the default branch): the checker read the board first and did not look the branch up again, and added its count with the command behind it; the verifier made its own two counts before reading the board, and confirmed. `agents.py --board` flagged neither. The checker also wrote the branch a second time as `repo.default_branch`, because the brief named no keys: the refusal above and the Keys line came from that. A second trial with the same brief (naming no keys) and the refusal in place: the checker tried `repo.default_branch`, was refused with `git.default_branch = main` named, read the board and wrote only its count; the board ended with two facts and no duplicate. Two trials on a trivial task, not a measurement of what the board saves.

## 0.1.0 (2026-11-19)

- Added: `/retro:distill`. `scripts/trace.py` digests a finished run's transcript: the task, the steps (repeats collapsed), each failure and the call after it, calls tried 3+ times, blocked calls, skills and sub-agents, the final answer. It reads Claude Code sessions (sub-agents from `<session>/subagents/`), role/content JSONL, and plain-text or markdown exports such as a Cursor chat, where each command's following prose is kept as what it observed. Emails, GUIDs, tokens, session links and user names in paths are masked. The skill drafts a SKILL.md (facts to resolve first, procedure, rules, gotchas, output, budget) under the scratchpad, lints it and installs it only on yes, for Claude Code or Cursor; `--update` turns a run into a diff to the skill it used and a row in that skill's run log.
- Added: `scripts/lint_skill.py`: frontmatter, a name that matches the folder, every `scripts/` or `references/` path the text names exists, and no private data (emails, GUIDs, tokens, session links, home paths) anywhere in the folder; warnings for no procedure, gotchas, output or budget.
- Added: `/retro:agent-audit`. `scripts/agents.py` measures each sub-agent from its own transcript: calls without its hand-back call, failures, the same call 3+ times, minutes, the budget its brief declared, the files it was asked for, writes and mutating commands under a read-only brief, its own count against the transcript's and the host's. Each problem gets an owner: brief (no budget, asks or deliverable paths, no context or rules, commands the main agent had already run, or that sibling agents each ran), execution, host (blocked, 401/403, a CLI missing) or model (a small model struggling on a clear brief; a large one finishing a trivial one). It records which skill was loaded when each brief was written, and rolls agents up by skill and by model: with `--all --skill NAME`, an eval of that skill's briefs across sessions. `--reports DIR` reads end-of-run report files for hosts whose sub-agent transcripts can't be read.
- Added: `references/brief-contract.md`, the brief shape (goal, context, numbered asks, rules, budget, deliverables, report file) and the report file's schema, used by `/inspector:audit`.
- Measured on one session (2026-11-19): a probe sub-agent's report said 4 tool calls, its transcript 3 and the host 3; the difference was its hand-back call, which the audit now names.

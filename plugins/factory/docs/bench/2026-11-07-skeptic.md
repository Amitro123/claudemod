# The skeptic, weighed both ways: 2026-11-07

The skeptic is meant to catch reviewer findings that aren't real before anyone acts on them. Across
this repository's whole-mod reviews it set aside nothing, while several findings turned out not to
be bugs. So it was tested on those findings, then changed.

## The cases (`evals/skeptic/`)

Real findings from those reviews, each run on a snapshot of the repository from before its fix:

| case | what it is |
|---|---|
| fp-design-other | followups: typing under "Other" sets the item's wording. A tested feature, not a bug. |
| fp-design-noreading | clawd-hud: "no reading yet" for an unreadable reset time. A comment says it is deliberate. |
| fp-engine-double-next | task-hud: ".catch calls next again and spawns twice". A probe showed the engine runs next once. |
| amb-slot-race | task-hud: two spawns get one slot. Not reproduced in the test engine: left unscored. |
| tp-goal-replan, tp-goal-add-stale | goal-run: the two majors, fixed with tests that failed before. |
| tp-brain-eval | brain-hud: an eval that could never pass. |
| tp-rtl-table | rtl-toggle: a table inside a blockquote breaks. |
| tp-hud-token | task-hud (a solo build): a token shown on a card. |

## Results (2 runs a case, Sonnet, as the factory runs the skeptic)

| skeptic | false positives set aside | real findings kept |
|---|---|---|
| before: "a finding you can't refute stands" | 0 of 6 | 10 of 10 |
| after: weighed both ways, with DESIGN and UNVERIFIED | 6 of 6 | 10 of 10 |

What the old skeptic said shows why it set nothing aside. On both design cases it found the comment
and still ruled STANDS ("the comment says this is deliberate... F1: STANDS"): it had no ruling for a
design choice. On the engine claim it ruled STANDS because it couldn't see the engine ("I found no
evidence that next is memoized, so I can't refute the finding"): what it couldn't refute stood.

The new one weighs a finding in both directions. A finding stands once its trigger, path and wrong
result are traced. A behaviour a test or comment makes deliberate is DESIGN, the person's call. A
claim resting on what can't be seen or run is UNVERIFIED, naming what would settle it, but only after
looking for what in the repository settles it. A first version without that last clause hedged one
real finding (the brain-hud eval) to UNVERIFIED; with it, none.

In factory 0.23.0 a review run's skeptic also weighs minor findings: two of the three false
positives were minor, and a full run's skeptic never saw them. A design or unverified finding goes to
no builder; the approver, the PR and Claude see it set apart, with its evidence.

Limits: eight scored cases from one repository, two runs each, one model. The eval is there to run
again on every change to the skeptic: `node plugins/factory/evals/skeptic/run.mjs [runs] [case ids]`.

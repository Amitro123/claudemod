# Does the factory pay for itself? Two small rounds, 2026-11-06

Headless Claude Code sessions with the same narrow permissions (file tools, git, the test runner).
Each task had a planted trap and hidden tests no agent saw; the person's part (approving the plan,
letting the checks run) was played by a script. One run per arm: a trend, not proof. Measured: time,
iterations, tool calls, what was caught, and whether the agents followed their instructions.

## Round 1: four small repositories (solo on Opus, the factory's builder on Sonnet)

| task (trap) | solo | factory |
|---|---|---|
| rounding, a copy of the logic in another file | hidden 3/3; 39 s, 3 tool calls | 3/3; 4 min, 42 calls, 1 builder round; escalated (billing) |
| a generated file | 3/3; 35 s, 8 calls | 3/3; 4.5 min, 43 calls, 1 round |
| parseDuration, edge cases | 2/2; 51 s, 9 calls; **its regex hangs: 10,000 spaces > 60 s** | 2/2; 8 min, 52 calls, 2 rounds: the code reviewer caught the regex (0 ms after the fix); escalated over a lockfile the factory's own setup made (fixed in 0.18.1) |
| config with a strict schema | 3/3; 68 s, 9 calls | 3/3; 4 min, 34 calls, 1 round |

## Round 2: two real tasks in this repository (every builder on Sonnet)

| | solo | factory | solo + review (hand-run) | solo + `/factory review` |
|---|---|---|---|---|
| task-hud: hidden tests | 3/3 | 3/3 | 3/3 | 3/3 |
| task-hud: a token shown on a card (9 probes) | **4 leak** | 2 leak (escalated, named) | 0 | 0 |
| task-hud: time, tool calls, iterations | 84 s, 13, 1 | 6.5 min, 72, 2 builder rounds | 3.2 min, 26, build + 1 fix | 3.6 min, 49, build + review + fix |
| rtl-toggle: hidden tests | 3/3 | 3/3 | 3/3 | 3/3 |
| rtl-toggle: time, tool calls, iterations | 75 s, 11, 1 | 6.5 min, 56, 2 builder rounds | 82 s, 16, build (review passed) | 2.5 min, 29, build + review + minor fixes |

The factory escalated both round-2 tasks because it ran no check: it didn't know `claude plugin test`
(fixed in 0.19.0).

## Were the instructions clear?

- The answer formats, yes: all 9 builder rounds ended with their `TESTS:` line, and all 18 reviews
  gave `UNDERSTOOD`, `VERDICT` and `NOT CHECKED`.
- Where they weren't, the runs showed it, and each is fixed:
  - 21 commands refused in the first run (`cd` before git, `git -C`, chains): the prompts now ask for
    one plain command per call and give the diff as a file (0.18.0).
  - The approver read "a reviewer couldn't run npm test" as "nobody ran it", though the factory's
    check had (0.18.0).
  - No one told the agents the project's test command: every refusal left after 0.18.0 was a guessed
    `bun test` in a repository that runs `claude plugin test`. The prompts now give the commands the
    factory ran or found (0.20.0).

## What it says

- Every real catch came from an independent reviewer: the hanging regex, the leaked tokens. The
  hidden tests passed everywhere; these are the bugs tests didn't catch.
- Each second builder round was spent on a real finding; none on a false one.
- The spec, the plan approval and the approver changed no outcome here, and cost the most time and
  the person's attention (a plan to approve, checks to allow, escalations that were mostly noise).
- So `/factory review` (0.19.0): the reviewers and the skeptic on the change in the checkout.

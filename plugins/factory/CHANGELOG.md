# Factory changelog

Earlier releases are described in the repository README.

## Unreleased

- Fixed (#154): the builder's commits carried the harness's `Claude-Session:` link, which a public repository would publish. The builder's prompt says to leave it out (Co-Authored-By is fine), and after each build the factory reads the branch's commit messages; one carrying a session link is rewritten with `git filter-branch --msg-filter` on the branch's own commits only (never a commit already on a remote, such as a merged-in base), `refs/original` is dropped, before anything is pushed, and the record says so. If it can't be taken out, the run stops for the person.
- Fixed (#171): the handed-out PR commands put the title in a double-quoted shell string, so an issue title with `$(...)` or backticks ran when pasted. Values from outside text are single-quoted, the default branch is looked up into `$BASE`, and the body is read from `pr-body.md`, so each line runs as pasted.
- Fixed (#172): `{owner}/{repo}` was left for gh to fill, and gh can pick an `upstream` remote in a fork. The repository is now origin's, read from its URL when the run starts; a run built on `upstream/<b>` opens its PR there with the fork owner's head.
- Fixed (#173): every `.tsx` file counted as UI, so a change to a hooks module added the ux and ui-design reviewers. A `.tsx`/`.jsx` file counts when its changed lines hold JSX, a class name, a style or a `$.ui` call.
- Fixed (#153): a restart of the session lost its runs, and starting the same feature again made a `-2` branch and built it all over. Each step now saves the run to `run.json` in its record. `/factory doctor` (and the status with no run) lists the runs an earlier session left, and `/factory resume [<run>]` picks one up at the step it was in (Retry semantics: that step's agent runs again; a build with commits goes through the post-build checks for leaks and session links; a plan waiting for approval is asked again; anything past the reviews goes back to the checks and a fresh review round, so saved verdicts aren't trusted). A saved state that doesn't match git's worktree and branch is not resumed. Starting a feature whose earlier branch is still there offers it instead of a new branch; `/factory new: <feature>` starts over.
- Fixed (#155): a check that fails without the change (a check that can't pass on the default branch) sent the builder back twice for nothing. A failing check is now run once on the run's base commit, in a detached worktree set up as the run's was; one that fails there the same way (the same failure output, durations aside) isn't sent to the builder, autoMerge holds off while it is red, the sync with the latest base doesn't count it, reviewers and the approver are told it fails on the base, and the record and the stats name it. The `baseFailures` option (`go-on`, default, or `stop`) says whether the run then goes on to review or stops for the person. A base that can't be checked out or set up changes nothing: the builder goes as before.
- Changed (#156): the default budgets follow the measured runs (`docs/bench/2026-11-19-budgets.md`), and reviewers are told not to run again the checks that passed on exactly their code.

Found by running a factory review of this repository's #149 and auditing its agents with `/retro:agent-audit`.

- Added: **a budget of tool calls per agent** (`budgets` in `.factory/config.json`, by role). Each agent's prompt ends with it; past twice it the guard refuses that agent's further tool calls, except its hand-back, telling it to answer with what it has, and the stats name it (`stopped at twice their budget`). `0` turns it off for a role. Counted per agent, not per role, so a reviewer's second round starts from zero. Before, nothing bounded an agent but the review rounds: the run's skeptic took 32 calls and none of its three agents' briefs named a number.
- Fixed: a finding the person fixed while a review ran was ruled REFUTED and counted against the reviewer. The skeptic reads the checkout as it is, and in that run 11 findings fixed during the review were set down as refuted, leaving the false-positive tally at "1 fixed, 11 refuted". The skeptic now has a FIXED ruling (real in the diff the reviewers read, gone from the code now), is told REFUTED means the reviewer was wrong about the code they read, and is told when the checkout's diff changed after the reviewers read it. A FIXED finding counts as fixed. The stats line counts only REFUTED rulings as refuted, and names those fixed while the review ran.
- Fixed: `claude plugin test` was detected for every plugin, and fails on a plugin with no hooks module ("no hooks module to load"). A plugin of skills and agents only now gets `claude plugin validate`; one whose `hooks/hooks.json` names modules still gets `claude plugin test`.

## 0.27.0 (2026-11-19)

Factory v2: the intake, the review route by risk, `.factory/config.json`, the gate on the latest base before the PR, `autoMerge`, cost per run, GitHub issues as the queue, and several runs at once. Also every fix listed below that was waiting for a release.


- Added: **the intake** (the `intake` option, on by default). Before the spec, an intake agent on opus weighs the feature, read as quoted data: ACCEPT with a scope the spec-writer is held to, NEEDS-INFO with up to three questions (`/factory rework <answers>` asks it again), or REJECT with why (`/factory approve` builds it anyway, recorded as the person's call). It names the risk (low, medium, high) and the surfaces (ui, security). An answer with no `INTAKE:` line decided nothing and waits for Retry; verdicts that disagree read as NEEDS-INFO, a missing risk as high, missing surfaces as both. The pane and the band draw it as its own step.
- Added: **the review route by risk** (with the intake on). Before each review round a script picks the reviewers from the intake's risk and surfaces and the diff: code always (haiku at low risk, sonnet otherwise, opus when the diff calls for depth); security on opus only for a security surface, high risk or a sensitive diff; `ux` (sonnet) and `ui-design` (haiku) for a UI surface or UI files in the diff. Rules only add review, and a reviewer that ran once runs every later round. A routed-out reviewer is drawn as skipped, left out of the approver's verdicts and named to it as routed out. The spec-writer, builder and approver run on opus. The route's reasons are in the run's record.
- Changed: the review route follows a table, `.factory/config.json` in the main checkout (`routing`, `surface_reviewers`), with the design's defaults: code on haiku at low risk and sonnet at medium and high; security (opus) only for a security surface or a diff that calls for depth (high risk alone no longer adds it); ux and ui-design for UI. A reviewer name of the project's own adds a reviewer.
- Added: `protected_paths` in `.factory/config.json`: a branch that modifies, renames or deletes a matching file fails the checks, and the builder is sent back with the list.
- Added: before the PR, the branch is synced with the latest base (`git fetch`, then a merge when the base moved on) and the checks run again; a conflict or a red check stops the run for the person (phase `merging`, blocked on `merge`).
- Added: the `autoMerge` option (off by default): on an approver's APPROVE, Claude merges the PR once it is open. Never after an escalation the person approved.
- Added: cost per run, API-equivalent, from each agent's usage by model and the prices in `.factory/config.json` (or the defaults): in the band, the pane, the status and `stats.md`.
- Added: **GitHub issues as the queue.** `/factory run` drains the open issues labeled `factory`, oldest first, one run at a time; `/factory run <n> [anyway]` runs one; `/factory queue` lists them; the start tool takes `issue`. The issue reaches the agents as a file of quoted data (`.factory/issues/<n>.md`, comments from its author and the operator only), never in a prompt. The intake's verdict is posted on the issue: NEEDS-INFO parks it with the `factory:needs-info` label until the author replies (the next `/factory run` resumes it with the answer), REJECT says why, an escalation adds `factory:needs-human`. The PR closes the issue. State per issue in `.factory/queue.json`.
- Added: **several runs at once** (the `concurrency` option, 3 by default). The session keeps every run by name (state `factory.runs`, replacing `factory.run`); each step carries its run's name, and each run's transitions are serialized on their own queue, so one run's checks don't hold up another. `/factory run` fills the free slots from the issue queue; a run waiting on the person holds none. Commands take a trailing `@#<issue>` or `@<run>`, the control tool a `run`; without one they act on the run that waits on the person, else the newest. The band shows a line per run, the pane the chosen run and the others, the status every run.
- Changed: the pane and the terminal lines show the merge gate (*latest base: checks again*, with the check running), and a reviewer the route left out as *not routed*.
- Fixed: an issue marked running in `.factory/queue.json` whose session ended before its run was done was skipped by every later `/factory run`; it now starts again.
- Credit: the intake, the routing table, protected paths, the re-gate before merge, cost per job, the issue queue and concurrent jobs follow the design of zazencodes' software-factory-claude-code-v2 (GPLv3); none of its code or prompts is copied here.
- Tests: the existing run tests pin `intake: 'off'` (the flow they describe); new tests cover the intake's verdicts, overrides and retry, and the route's reviewers and models.
- Fixed: a Stop pressed while a step awaited something before moving the run on (the review route's git diff, the checks' setup, the approver's diff) was undone: the step moved the stopped run back to review, checks, build, approve or ready, and started its agents. A run that is no longer live now never moves to another phase, and each step starts its agents only if the run is in that step's phase.
- Fixed: in a review of the person's checkout, a path under `/tmp` with a `..` segment (`echo x > /tmp/../src/a.ts`, `cp a /tmp/../src/a.ts`) counted as a `/tmp` scratch file, so it could write the checkout. A `..` segment now never counts as `/tmp`.
- Fixed: a Stop pressed while the skeptic was starting didn't hold when that start then failed: the run went back to review and the findings went to a builder. The failed start now resumes the run only from the stop it made itself; a stopped run stays stopped. An approval queued before a Stop no longer asks Claude for the PR either.
- Fixed: in a review of the person's own checkout, the reviewers and the skeptic could change it through Bash (only Edit and Write were refused), so a stray `git stash` or `git checkout -- .` could lose uncommitted work. A review's agents are now refused git commands that change the checkout, its index or its branch, `sed -i` and other in-place edits, dependency installs, `rm`/`mv`/`cp`/`tee`/`touch` and redirects into files outside `/tmp`. Writes under `/tmp` stay allowed. Like the push guard, it guards against mistakes; it is not a security boundary.
- Fixed: check detection dropped every folder above a touched file that sits in a hidden or ignored folder. A change only to `plugins/x/.claude-plugin/plugin.json` ran no `claude plugin test plugins/x`. The walk now runs from the top down and stops at the first such folder.
- Fixed: a file the builder staged itself as a rename to `.env` (`git mv config.txt .env`) passed the staged-file check before the factory's commit, because git reported a rename and the check asked for added files. It now passes `--no-renames`, as the history scan does (which already caught it one step later).
- Fixed: a credential the builder committed and then deleted, or renamed to an ordinary name, passed the check before the checks run and was pushed with the branch, because the check compared only the base and HEAD trees. An ordinary file of the base renamed to `.env` passed too (git reported a rename, not an added file), and so did a file a merge commit added. The check now reads every commit between the base and HEAD (`git log --no-renames --diff-merges=first-parent --diff-filter=A --name-only -z`): a rename counts as a delete and an add with no similarity guess, a merge commit is compared with its first parent, and the merged branch's own commits are read as well. A match stops the run for the person, naming each path and the short ids of the commits that added it. A scan git cannot complete (an unknown base, a git error) now stops the run instead of reading as clean. Nothing is removed or rewritten automatically.
- Fixed (PR #122 review): with `log.showSignature=true` in the person's git config and signed commits, git printed signature text into the scan's output and a committed `.env` read as clean (the check before it, on the net diff, caught it). The scan now passes `--no-show-signature`, and output in any other shape than it asked for (a field before the first commit, a commit id that isn't 40 or 64 lowercase hex digits, a path out of place, no closing NUL) stops the run for the person like a failed scan, instead of being read as clean. Empty output (no commits since the base) is still a clean scan; paths are taken as git wrote them, NUL-separated, with only the one newline git puts before a commit's first path removed. Tested against real git with commits signed by a throwaway SSH key and `log.showSignature` in the test repository's own config (`ssh-keygen` and git 2.34+ needed; the test fails rather than skips without them, and CI checks for `ssh-keygen` first).
- Limitation: the check goes by file name, with the same never-commit list as before (`.env` and `.env.*` except samples, `*.pem`, `*.key`, `*.p12` and `*.pfx` outside test folders, installed dependencies). It reads no file contents, so a secret inside an ordinary file is not caught, nor is a credential already in the base and only renamed or deleted on the branch. Commits a merge brings in count as the branch's own, so a credential an upstream branch merged into the work added stops the run too.
- Tests: `tests/history.real-git.mjs` runs the scan against real git in disposable repositories (`node --experimental-strip-types --test plugins/factory/tests/history.real-git.mjs`, from the repository root; Node 22.12+, git 2.31+; `claude plugin test` cannot start a process). CI runs it as its own `factory-history` job in `.github/workflows/mods.yml`, beside the kit tests, so it runs and can fail on its own. The never-commit rules moved unchanged from `hooks/flow.ts` to `hooks/history.ts`, which has no imports so plain Node can load it; `flow.ts` re-exports them.

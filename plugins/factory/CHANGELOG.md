# Factory changelog

Earlier releases are described in the repository README.

## Unreleased

- Fixed: a Stop pressed while a step awaited something before moving the run on (the review route's git diff, the checks' setup, the approver's diff) was undone: the step moved the stopped run back to review, checks, build, approve or ready, and started its agents. A run that is no longer live now never moves to another phase, and each step starts its agents only if the run is in that step's phase.
- Fixed: in a review of the person's checkout, a path under `/tmp` with a `..` segment (`echo x > /tmp/../src/a.ts`, `cp a /tmp/../src/a.ts`) counted as a `/tmp` scratch file, so it could write the checkout. A `..` segment now never counts as `/tmp`.
- Fixed: a Stop pressed while the skeptic was starting didn't hold when that start then failed: the run went back to review and the findings went to a builder. The failed start now resumes the run only from the stop it made itself; a stopped run stays stopped. An approval queued before a Stop no longer asks Claude for the PR either.
- Fixed: in a review of the person's own checkout, the reviewers and the skeptic could change it through Bash (only Edit and Write were refused), so a stray `git stash` or `git checkout -- .` could lose uncommitted work. A review's agents are now refused git commands that change the checkout, its index or its branch, `sed -i` and other in-place edits, dependency installs, `rm`/`mv`/`cp`/`tee`/`touch` and redirects into files outside `/tmp`. Writes under `/tmp` stay allowed. Like the push guard, it guards against mistakes; it is not a security boundary.
- Fixed: check detection dropped every folder above a touched file that sits in a hidden or ignored folder. A change only to `plugins/x/.claude-plugin/plugin.json` ran no `claude plugin test plugins/x`. The walk now runs from the top down and stops at the first such folder.
- Fixed: a file the builder staged itself as a rename to `.env` (`git mv config.txt .env`) passed the staged-file check before the factory's commit, because git reported a rename and the check asked for added files. It now passes `--no-renames`, as the history scan does (which already caught it one step later).
- Fixed: a credential the builder committed and then deleted, or renamed to an ordinary name, passed the check before the checks run and was pushed with the branch, because the check compared only the base and HEAD trees. An ordinary file of the base renamed to `.env` passed too (git reported a rename, not an added file), and so did a file a merge commit added. The check now reads every commit between the base and HEAD (`git log --no-renames --diff-merges=first-parent --diff-filter=A --name-only -z`): a rename counts as a delete and an add with no similarity guess, a merge commit is compared with its first parent, and the merged branch's own commits are read as well. A match stops the run for the person, naming each path and the short ids of the commits that added it. A scan git cannot complete (an unknown base, a git error) now stops the run instead of reading as clean. Nothing is removed or rewritten automatically.
- Fixed (PR #122 review): with `log.showSignature=true` in the person's git config and signed commits, git printed signature text into the scan's output and a committed `.env` read as clean (the check before it, on the net diff, caught it). The scan now passes `--no-show-signature`, and output in any other shape than it asked for (a field before the first commit, a commit id that isn't 40 or 64 lowercase hex digits, a path out of place, no closing NUL) stops the run for the person like a failed scan, instead of being read as clean. Empty output (no commits since the base) is still a clean scan; paths are taken as git wrote them, NUL-separated, with only the one newline git puts before a commit's first path removed. Tested against real git with commits signed by a throwaway SSH key and `log.showSignature` in the test repository's own config (`ssh-keygen` and git 2.34+ needed; the test fails rather than skips without them, and CI checks for `ssh-keygen` first).
- Limitation: the check goes by file name, with the same never-commit list as before (`.env` and `.env.*` except samples, `*.pem`, `*.key`, `*.p12` and `*.pfx` outside test folders, installed dependencies). It reads no file contents, so a secret inside an ordinary file is not caught, nor is a credential already in the base and only renamed or deleted on the branch. Commits a merge brings in count as the branch's own, so a credential an upstream branch merged into the work added stops the run too.
- Tests: `tests/history.real-git.mjs` runs the scan against real git in disposable repositories (`node --experimental-strip-types --test plugins/factory/tests/history.real-git.mjs`, from the repository root; Node 22.12+, git 2.31+; `claude plugin test` cannot start a process). CI runs it as its own `factory-history` job in `.github/workflows/mods.yml`, beside the kit tests, so it runs and can fail on its own. The never-commit rules moved unchanged from `hooks/flow.ts` to `hooks/history.ts`, which has no imports so plain Node can load it; `flow.ts` re-exports them.

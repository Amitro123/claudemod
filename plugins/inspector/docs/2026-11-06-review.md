# inspector 0.1 → 0.2: an EGM review and two backtests

2026-11-06. How the `inspect` skill was checked before tuning it, what was found, and what changed.

## Method

Two checks, both run by agents that saw none of the conversation that wrote the skill.

1. **The Elephant-Goldfish review** ([google/elephant-goldfish-model](https://github.com/google/elephant-goldfish-model), its
   consolidated preset). Eight reviewers read `SKILL.md`, its references, the collector and its
   tests, each through its EGM persona file:
   - zoom-out and inventive catalyst (stage 5);
   - comprehension (stage 6);
   - design critic, structural and style (stage 7);
   - implementation readiness and codebase details (stage 9).

   For a skill, "implementation" means an agent carrying it out. After the fixes, a stage 8
   zoom-out read the revised skill.
2. **A backtest.** EGM checks the document, not whether the skill finds anything, so this check
   was added on the same principle (a fresh agent, no context):
   - The repository was cut at PR #50 (2026-10-28) into a clone with no history after it.
   - An agent ran the skill on that clone, with no network and no access to anything later.
   - Its open leads were scored against the 71 commits of #51–#72: the bugs that were actually
     found and fixed afterwards.
   - Each lead not fixed there was checked against today's code (main at #72).

   It ran once with 0.1.0 and once with 0.2.

[microsoft/SkillOpt](https://github.com/microsoft/SkillOpt) was the other option. It trains a skill against a scored task set
(train/val/test) with an optimizer model. It needs that task set and an API key, and here one
task is a whole investigation. The backtest above is the scorer such a set would need; see
"Next".

## Backtest results

| | 0.1.0 | 0.2 |
|---|---|---|
| Fixes found by the collector (of 55 units) | 31 | 16 (corrected to 18 by the agent) |
| Open leads | 8 | 6 |
| … fixed later in #51–#72 | 4 exactly + 1 in part | 1 + 1 in part (the same race) |
| … not fixed there, and still true on today's main | 2 | 4 |
| … undetermined | 1 (Windows paths) | 0 |
| False leads | 0 | 0 |
| Leads seen failing (reproduced) | not separated from read | 4 of 6 |
| Cost | ~216k tokens, 12 min | ~237k tokens, 15 min |

Both versions found real bugs at a high rate. Version 0.2 reported fewer leads that later fixes
confirmed. It reported more bugs that are still open today, and more leads it had seen fail.
The six bugs that the backtests found still open on today's main:

| Bug | Where | Found by |
|---|---|---|
| A `done` note with a line break isn't recognised: goal-run doesn't close the task, brain-hud makes no offer | `shared/texts.ts` `doneResult`/`parseDoneResult` | 0.1.0 |
| `DB_PASSWORD=`, `GITHUB_TOKEN=` (a keyword after `_`) reach MISTAKES.md unredacted | `mistake-brain/scripts/host_layout.py` | 0.1.0 |
| A sub-agent report's section runs on past `## Next steps`; `Open items:` isn't read; fenced text is | `brain-hud/hooks/journal.ts` `reportSections` | 0.2 |
| The exclude line `.claude/brain/` is anchored at the repository top: a project in a subfolder can commit its journal | `brain-hud/hooks/register.tsx` `keepOutOfGit`, `init_project.py` | 0.2 |
| Two sessions starting different tasks leave two tasks in progress after a merge | `goal-run/hooks/register.tsx` `mergeGoal` | 0.2 |
| An index line with an en dash is not parsed by `rebuild_index.py`, so the file is listed twice | `rebuild_index.py` `_LINE` vs `brain.ts` | 0.2 |

**The two runs' leads barely overlap** (one in common, the race between two sessions; 13 distinct
real bugs between them). With a budget of 12 cases, a run samples part of the history. So two runs,
or a larger budget, find more, and the budget and the triage order are what tuning should set.

## What the review found, and what was done

**Fixed in the collector (`scripts/evidence.py`)**, each with a test:

| Finding (reviewers) | Change |
|---|---|
| Two thirds of units read as fixes: weak words ("review", "found", "never"), every commit body scored, "fix lint" counted (design, catalyst, codebase) | The verdict reads titles and commit subjects in strong words only; housekeeping commits don't count; a unit is a fix by its title, by most of its commits, or as a patch-only release. 31 → 16 on the backtest repo, 52 → 28 on today's. |
| Version bumps paired across files, string-sorted, lockfile `"version"` lines read (design, codebase) | Per manifest, numeric, top-level only; a release that also bumps a minor version is a feature |
| A rename-and-edit fix lost its culprit: `--diff-filter=MD` (codebase; reproduced) | Renames are blamed on the old path; blame runs with `-M` and honours `.git-blame-ignore-revs` |
| Octopus merges kept one branch's commits (codebase; reproduced) | Every merged branch |
| Instruction Markdown (`SKILL.md`, agents, prompts) never blamed, so prompt bugs had no culprit (zoom-out, catalyst, design) | Blamed like code; READMEs, changelogs, manifests and lockfiles still aren't |
| A culprit just before `--since` was never known to be a fix (catalyst) | Attribution maps to the last 500 units whatever the work window |
| `#N`, sha and path scopes had no flag; `#N` older than 200 units missing (readiness, zoom-out, design, codebase) | `--unit`, `--path`, `--show`; a Warning when the window is cut |
| Shallow boundary commit diffed against the empty tree (codebase; reproduced) | Listed, not judged, with a Warning |
| Blame per unit, so a review-fix PR split into cases had no culprit per case (readiness) | Blame per fix commit, kept per commit too |
| Tests counted as hotspots; regex precedence; output folder must exist; `base` not in the JSON (design, codebase) | Fixed |

**Fixed in `SKILL.md` and its references:**
- `<scratch>` defined;
- one list of what may be written;
- a flag for each scope;
- a 12-case budget with a reserved random check;
- one case per bug, with rules for commits that fix several things;
- the levels reproduced / read / blame / inferred, used by cases and leads;
- seam as a field beside the class (the taxonomy's "seam" class became "interference");
- exact worktree commands with a cost bound;
- a check before writing the case file;
- where an earlier case file is found;
- a Limits section;
- paths under `<skill_root>`;
- repository text treated as data, also when handed to sub-agents.

**Contested:**
- Structural and design asked for "Alternatives considered" and "Risks" sections, as a design
  document has. The skill is instructions an agent loads, and long sections cost on every run, so
  the trade-off went into one Limits bullet instead.
- Catalyst's changelog-as-oracle and design's PR grouping through the host API for rebase-merge
  repositories are deferred: both add parsing that can drift. Each is named in Limits.
- `blame -C` (moves between files) is deferred for its cost.

**Stage 8** (after the fixes) found all nine earlier findings resolved. It found two Majors the
revision itself added:
- an "Unworked" carry-over between runs that the collector couldn't act on: dropped;
- a sub-agent protocol for a case the budget rules out: cut to one sentence.

## Next

- **Tuning:** the budget and the triage order decide what a run finds. The backtest is now a
  scorer: the repository cut at a PR, and the later fixes as the key. Cut at three or four points
  (#25, #40, #50, #60), it makes a small task set for comparing settings, or for SkillOpt.
- **The six open bugs above:** worth fixing; each lead in the backtest case files names the change
  and the test.
